## 2. THE STRATEGIC PROBLEM, STATED PLAINLY

Q-Trust has two possible papers. Only one of them is true.

### Paper A — "We built a PQC migration system with a GNN planner and a CodeBERTa
### discovery model, achieving F1 0.9525 and matching the migration doctrine."

**This paper cannot be written.** Every load-bearing number is either circular,
irreproducible, or both:

| Claim | Status |
|---|---|
| F1 0.9525 | Labels generated by the evaluated detector; corpus + weights absent; +0.084 over "always predict crypto"; **0.280 better than rules-only on micro-F1 but 0.080 WORSE on macro-F1** |
| "GNN reproduces doctrine (honest tie)" | Base checkpoint trained on 40/42 held-out CBOMs; baseline **is** the label function; graphs have **zero edges**; **a bare key-size sort scores identically on 42/42 folds** |

Writing Paper A would require either fabricating results or making claims that a reviewer
can refute in an afternoon with the public repository. **Do not write it.**

### validity — each detectable only by recomputation from its own artifacts."

**This paper is true, fully supported today, and genuinely useful.**

## 3. WHY PAPER B IS A REAL CONTRIBUTION

Three reasons, each externally grounded:

**(a) The gap is real and documented.** A targeted literature review found:
- **No published work on PQC migration *ordering* as a learned ranking problem.** The
  closest work is Hasan et al. (IEEE Access 2024), which is graph-theoretic and
  non-learned; and Shaw (arXiv:2610.09029), which is analytic and explicitly *"not
  validated against outcomes."*
- **No published GNN for cryptographic asset ranking.** Only vendor marketing claims.
- **No public host-level TLS/CBOM dataset with ground-truth labels.** The available
  corpora (Censys/IMC'13, EFF SSL Observatory, Chung et al./CCS'16, Heninger et al./USENIX
  Sec'12) are **census data, not labelled data** — there is no ground-truth "this host
  should migrate first."

So the field needs migration-ordering infrastructure *and* has no oracle to validate it
against. That combination is precisely what makes Q-Trust's evaluation failure generalisable
rather than idiosyncratic.

**(b) The failure taxonomy is transferable.** Each mode has a cheap detection check that
any reviewer could run:

| Mode | Detection check | Cost |
|---|---|---|
| Warm-start contamination | Read `n_real_graphs` in checkpoint metadata vs the eval corpus | seconds |
| Circular baseline | `diff` the baseline function against the label function | seconds |
| Degenerate graph structure | Count `edge_index` elements | seconds |
| Tie-saturated rank metric | Count discordant pairs; report SE | seconds |
| Vacuous top-*k* | Check `k > n` | seconds |
| Non-random "random" baseline | Check the RNG seed | seconds |
| Time-dependent labels | Grep for `datetime.now()` in the label path | seconds |

**(c) It preserves the project's real strengths.** Q-Trust's committed per-case raw records
(`benchmarks/external/`), its `TRUTH_AUDIT.md` provenance-labelling discipline, its
`dvc.yaml` honest-failure design, and its CycloneDX conformance suite are all genuine and
independently verifiable. The audit framing uses them; it does not discard them.

## 4. RESEARCH QUESTIONS

**RQ1.** Which published PQC-migration-ordering and crypto-discovery results survive
independent recomputation from their own committed artifacts, and which do not?

**RQ1b.** Does superior artifact hygiene (committed predictions, audited splits, bootstrap
CIs, reconciled documentation) predict evaluative validity? *Answered no:* a second system
with strictly better hygiene than the first fails the same failure mode.

**RQ2.** What is the statistical resolution of a host-disjoint leave-one-out ranking
benchmark built from n real certificate assets, and what effect sizes can it detect?

**RQ3.** When a reported improvement is a difference between two *averaging strategies*
over the same predictions, how is that difference distributed?

**RQ4.** Is provenance labelling (REAL / SYNTHETIC / DEMO) sufficient to establish
evaluative validity? We hypothesize **no**, and we demonstrate it on a system that passes
its own provenance audit.

Each RQ is answerable from data in the public repository today. **No RQ requires the
missing datasets, a GPU, or expert annotation.** That is deliberate: it is what makes the
paper completable now.

## 5. CONTRIBUTION STATEMENT (as it should appear in the paper)

1. A **six-mode taxonomy** of evaluative-validity failures in a real deployed ML
   evaluation, each demonstrated with a file/line citation, a committed artifact, an
   independent recomputation, and a cheap detection check.
2. A **reconstruction-validated re-audit harness** that reproduces the benchmark's own
   headline numbers bit-exactly (42/42 folds) from the public repository, then measures
   what those numbers can and cannot support.
3. The finding that on the audited corpus the **learned ranker is provably redundant with a
   single-feature sort** (identical metric vectors on 42/42 folds), because the label
   function degenerates to a monotone function of one column.
4. The finding that a **reported +0.280 F1 gain over a deterministic baseline flips sign to
   −0.080** under macro-averaging.
5. An **evidence ledger and honesty analysis** separating provenance-labelling adequacy
   from evaluative validity, showing that a project with a rigorous REAL/SYNTHETIC/DEMO
   taxonomy can still ship six mutually-concealing validity failures.
6. A **reproducible audit package** (stdlib-only verification harness, six-experiment
   re-audit script, figure generator) that runs on a fresh clone.

## 6. WHAT WE DELIBERATELY DO NOT CLAIM

- We do **not** claim the GNN is broken as software. It trains, converges, and matches a
  ceiling that is set by the label function.
- We do **not** claim the authors were dishonest. **All 14 headline numbers reproduce
  exactly.** The failure mode is construct validity, not arithmetic.
- We do **not** claim our audit is exhaustive, only that these six modes are present,
  independent, and mutually concealing.
- We do **not** claim vendor GNN products do not work — only that they publish no evidence.
